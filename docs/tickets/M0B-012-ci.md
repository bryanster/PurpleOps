# M0B-012 — CI: lint, test, build matrix, codegen-drift gate

**Milestone:** M0b · **Size:** M · **Depends on:** M0B-011

## Why

`PLAN.md` §7 requires every milestone to "end green on CI". Two gates in particular are non-
negotiable and both come from named v1 failures: **codegen drift** (§4 — "CI fails if generated code
is stale") and **cross-compilation with CGO** (§8 — the risk is accepted only because CI proves the
builds work).

## Scope

**In**

- `.github/workflows/ci.yml` running on push and pull request:
  | Job | Does |
  |---|---|
  | `lint` | `golangci-lint`, `npm run lint`, `tsc --noEmit`, OpenAPI spec lint |
  | `test-go` | `go test -race -coverprofile ./...` |
  | `test-web` | `npm test` |
  | `codegen` | `make generate && git diff --exit-code` |
  | `build` | Matrix `linux/amd64` + `linux/arm64`, CGO on, with cross-compilers |
  | `docker` | Builds the image and runs the smoke script from `M0B-011` |
  | `e2e` | Playwright (`M0B-013`) — may be added by that ticket |
- Dependency caching for Go modules, the Go build cache, and npm.
- `.github/dependabot.yml` for gomod, npm, and github-actions.
- Branch-protection settings documented in `docs/contributing.md` (required checks, no direct pushes
  to the default branch, linear history).
- Concurrency group so a new push cancels the previous run for the same branch.

**Out**

- Release/publishing workflow — M7.
- Anything requiring secrets. CI must be fully functional on a fork PR.

## Acceptance criteria

- [ ] All jobs pass on the current branch.
- [ ] The `codegen` job **fails** on a PR that edits `api/openapi.yaml` without committing
      regenerated code. Prove it with a throwaway commit and include the failing run link in the PR.
- [ ] The arm64 build genuinely produces an arm64 binary (`file bin/purpleops` output pasted in the
      PR), not a silently-native one.
- [ ] `go test -race` is used, not plain `go test`.
- [ ] Total wall-clock for the required checks is under 10 minutes on a warm cache. If not, say what
      dominates.
- [ ] Cache keys include the relevant lockfile hashes, so a dependency bump doesn't reuse a stale
      cache.
- [ ] The workflow does not use `continue-on-error` or `|| true` anywhere. A check that can't fail
      isn't a check.
- [ ] Third-party actions are pinned to a commit SHA, not a floating tag.

## Tests

CI is its own test. The verification is the demonstrated red run for the drift gate.

## Notes for the implementer

- CGO cross-compilation to arm64 from an amd64 runner needs `gcc-aarch64-linux-gnu` and
  `CC=aarch64-linux-gnu-gcc`. The alternative is a native arm64 runner — either is fine, pick one
  and note why.
- Coverage: publish the number, do not gate on a threshold. Percentage targets push people to test
  getters; the per-layer requirements in `PLAN.md` §9 are the real bar.
