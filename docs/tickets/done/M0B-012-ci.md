# M0B-012 — CI: lint, test, build matrix, codegen-drift gate

**Milestone:** M0b · **Size:** M · **Depends on:** M0B-011

## Why

`PLAN.md` §7 requires every milestone to "end green on CI". Two gates in particular are non-
negotiable and both come from named v1 failures: **codegen drift** (§4 — "CI fails if generated code
is stale") and **cross-compilation with CGO** (§8 — the risk is accepted only because CI proves the
builds work).

## Scope

**In**

- `.github/workflows/ci.yml` running on push and pull request:
  | Job | Does |
  |---|---|
  | `lint` | `golangci-lint`, `npm run lint`, `tsc --noEmit`, OpenAPI spec lint |
  | `test-go` | `go test -race -coverprofile ./...` |
  | `test-web` | `npm test` |
  | `codegen` | `make generate && git diff --exit-code` |
  | `build` | Matrix `linux/amd64` + `linux/arm64`, CGO on, with cross-compilers |
  | `docker` | Builds the image and runs the smoke script from `M0B-011` |
  | `e2e` | Playwright (`M0B-013`) — may be added by that ticket |
- Dependency caching for Go modules, the Go build cache, and npm.
- `.github/dependabot.yml` for gomod, npm, and github-actions.
- Branch-protection settings documented in `docs/contributing.md` (required checks, no direct pushes
  to the default branch, linear history).
- Concurrency group so a new push cancels the previous run for the same branch.

**Out**

- Release/publishing workflow — M7.
- Anything requiring secrets. CI must be fully functional on a fork PR.

## Acceptance criteria

- [x] All jobs pass on the current branch. — [run
      30713779843](https://github.com/bryanster/blacklight/actions/runs/30713779843), green on the
      first attempt.
- [x] The `codegen` job **fails** on a PR that edits `api/openapi.yaml` without committing
      regenerated code. Prove it with a throwaway commit and include the failing run link in the PR.
      — [run 30713816484](https://github.com/bryanster/blacklight/actions/runs/30713816484) (PR #46,
      since closed and the branch deleted).
- [x] The arm64 build genuinely produces an arm64 binary (`file bin/blacklight` output pasted in the
      PR), not a silently-native one. — asserted by the workflow itself, not only by eye. See below.
- [x] `go test -race` is used, not plain `go test`.
- [x] Total wall-clock for the required checks is under 10 minutes on a warm cache. If not, say what
      dominates. — **1m 38s cold**, no warm cache needed. Per-job times below.
- [x] Cache keys include the relevant lockfile hashes, so a dependency bump doesn't reuse a stale
      cache. — `cache-dependency-path: go.sum` and `web/package-lock.json`.
- [x] The workflow does not use `continue-on-error` or `|| true` anywhere. A check that can't fail
      isn't a check.
- [x] Third-party actions are pinned to a commit SHA, not a floating tag.

## Tests

CI is its own test. The verification is the demonstrated red run for the drift gate.

## Notes for the implementer

- CGO cross-compilation to arm64 from an amd64 runner needs `gcc-aarch64-linux-gnu` and
  `CC=aarch64-linux-gnu-gcc`. The alternative is a native arm64 runner — either is fine, pick one
  and note why.
- Coverage: publish the number, do not gate on a threshold. Percentage targets push people to test
  getters; the per-layer requirements in `PLAN.md` §9 are the real bar.

## Implementation notes

**Files.** `.github/workflows/ci.yml`, `.github/dependabot.yml`, `docs/contributing.md`, and two new
Makefile targets — `test-race` and `print-golangci-version`. `README.md` gains the badge and a link
to the contributing guide.

**The drift gate was verified red before it was believed.** PR #46 renamed one `operationId` in
`api/openapi.yaml` and deliberately did not run `make generate`. Result: `Generated code is current`
failed, and **every other job passed** — lint, both builds, the race tests and the container smoke
test. That is the finding worth keeping. Stale generated code compiles, passes its tests and ships;
this job is the only thing in the pipeline that can see it. The check is `git status --porcelain`
rather than `git diff --exit-code` alone, because the latter is blind to a generator that starts
emitting a *new* file, and it prints the offending diff into the log so the fix is obvious without
re-running anything locally.

**Cross-compilation from one amd64 runner, not a native arm64 runner.** Both were viable — this
repository is public, so `ubuntu-24.04-arm` is free — and the tie-breaker is that
`deploy/Dockerfile` cross-compiles (M0B-011: emulated builds segfault the Go toolchain at a random
package). A native runner would prove that *some* arm64 build works; cross-compiling proves the one
we actually ship does. `gcc-aarch64-linux-gnu` **and** `g++-aarch64-linux-gnu`, because the DuckDB
engine is a C++ static archive and the link needs the target's `libstdc++` — the same reason the
Dockerfile installs the C++ package.

The arch assertion is a step in the workflow rather than something a reviewer eyeballs once:

```
bin/blacklight: ELF 64-bit LSB executable, ARM aarch64, version 1 (GNU/Linux), dynamically linked,
               interpreter /lib/ld-linux-aarch64.so.1, for GNU/Linux 3.7.0
bin/blctl:   ELF 64-bit LSB executable, ARM aarch64, version 1 (SYSV), statically linked
```

A toolchain that quietly ignored `GOARCH` would otherwise produce two green amd64 builds, one of
them labelled arm64, and nobody would find out until an arm64 operator ran the image. Both `file`
strings were confirmed in a container before the workflow was written, so the matcher was not
guesswork.

**Timings, cold cache, first ever run: 1m 38s wall clock.**

| Job | Time |
|---|---|
| Web tests | 27s |
| Go tests (`-race`, coverage) | 1m 04s |
| Generated code is current | 57s |
| Build linux/amd64 | 1m 07s |
| Lint | 1m 13s |
| Build linux/arm64 | 1m 22s |
| Container smoke test | 1m 22s |

Nothing dominates enough to be worth optimising, and the ticket's 10-minute budget is not close.
The container job was the one expected to blow it — it builds the whole image from scratch, Chromium
included, on every run — and it does that in about 70 seconds, so the BuildKit layer cache that had
been planned for it was not added. Layer caching via `type=gha` is the obvious lever if that ever
changes; it was left out because it needs either a third-party action to expose the runtime token or
`actions/cache` round-tripping ~600 MB, and neither is worth it to save a minute.

**Go coverage is 76.7%**, published to the run summary and uploaded as an artifact. Not gated, per
the ticket.

**One required check, `CI`, not seven.** It `needs` every other job, runs with `if: always()`, and
fails on any result that is not `success` — which includes `skipped` and `cancelled`. This matters
twice: `M0B-013` can add an `e2e` job without anyone touching the repository settings, and a job
that fails to *start* cannot be mistaken for a job that passed, which is the classic way a required
check quietly stops checking.

**`golangci-lint` comes from the action, not from `make lint`.** The Makefile installs it with
`go install`, which is right locally and is two to three minutes of compiling a large dependency
tree on a cold runner. The action fetches the same pinned release prebuilt. To stop the pin living
in two places, the workflow reads it from the Makefile via `make print-golangci-version` — the same
trick `internal/version`'s ldflags test already uses for `print-ldflags`.

**`make test-race` is a separate target from `make test`.** `-race` roughly triples the wall clock,
which is the wrong default for the loop a developer runs every few minutes and the right one before
merging. `COVERPROFILE` defaults to `coverage.out`, which `*.out` in `.gitignore` already covers, so
running it locally cannot dirty the tree the codegen gate inspects.

**Branch protection is documented, not applied.** `docs/contributing.md` records the intended
ruleset — required `CI` check, no direct pushes including for administrators, linear history, no
force pushes or deletions, conversation resolution — because GitHub's UI is not in version control
and a protection rule that silently disappears is the same as never having had one. Someone with
admin rights still has to set it.

**Dependabot covers three ecosystems.** `gomod` and `npm` (rooted at `/web`, where `package.json`
lives) are grouped so one pull request a month carries the whole tree; npm is split into production
and development groups so a routine devDependency patch is not blocked behind a React or Vite major.
`github-actions` is the one that matters for this ticket: it rewrites the SHA pins *and* the
`# vX.Y.Z` comment beside them, which is what makes commit-pinned actions sustainable rather than a
thing everybody stops updating after two months.

**Not done here.** The `e2e` job is `M0B-013`'s, as the ticket allows. There is no release or
publishing workflow — that is M7.
