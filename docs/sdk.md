# The client SDKs

Four clients live in [`sdk/`](../sdk), generated from
[`api/openapi.yaml`](../api/openapi.yaml) — the same document the server is generated from:

| Language | Package | Generator | Pinned by |
|---|---|---|---|
| Go | [`sdk/go`](../sdk/go) | `oapi-codegen` | `go.mod` (`tools/tools.go`) |
| TypeScript / JavaScript | [`sdk/typescript`](../sdk/typescript) | `openapi-typescript` + `openapi-fetch` | `sdk/typescript/package-lock.json` |
| Python | [`sdk/python`](../sdk/python) | `openapi-python-client` | `tools/pygen/uv.lock` |
| Rust | [`sdk/rust`](../sdk/rust) | `openapi-generator` (container) | image digest in `tools/generate-rust-sdk.sh` |

Each has its own README with the usage a caller needs. This page is about how they are produced and
why they are produced that way.

```
make generate     # rewrite all four from api/openapi.yaml
make test-sdk     # run their tests (Go, TypeScript, Python, Rust)
```

The output is **committed**, like `internal/httpapi/gen/server.gen.go` and
`web/src/api/schema.d.ts` before it, and the `codegen` job in CI regenerates everything and fails if
the result differs from what is in the tree. Editing `api/openapi.yaml` without committing four
regenerated SDKs does not merge.

## Four generators rather than one

`openapi-generator` can emit all four languages from one configuration, and that is not what this
repository does. Two reasons:

1. **The document is OpenAPI 3.1**, and uses it: 36 `type: [x, "null"]` unions, whose whole point is
   that "absent" and "explicitly null" are different — the distinction the `PATCH` endpoints depend
   on. `openapi-generator` reads 3.1 by converting it to 3.0 internally, where that distinction does
   not exist. The Go, TypeScript and Python generators read 3.1 natively.
2. **Two of the four were already here.** `oapi-codegen` generates the server, so generating the Go
   client with the same tool at the same version means one program decides what a nullable field or
   a prefixed enum constant is on both sides of the wire. `openapi-typescript` generates the SPA's
   types. Introducing a second opinion about the same document, in the two languages this repository
   already had a good answer for, would be a step backwards.

Rust is the exception, and it is the reason `openapi-generator` is here at all: there is no Rust
generator that reads OpenAPI 3.1. `progenitor`, the obvious candidate, is 3.0-only, so using it
would mean maintaining a 3.1 → 3.0 downconverter of our own and a second, derived copy of the
document. Running the Java generator inside a container pinned by digest keeps the JDK out of
everyone's machine and produces the same bytes everywhere.

## Where each one comes from

**Go** is generated by the `//go:generate` line in [`api/spec.go`](../api/spec.go), from
[`api/codegen-sdk-go.yaml`](../api/codegen-sdk-go.yaml) — right beside the server's own config, so
the two are read together. `sdk/go` is a **separate Go module**: `go get` of the client must not
drag DuckDB, chromedp and the SSO stacks into someone else's build.

**TypeScript** is `npm --prefix sdk/typescript run generate`, the same `openapi-typescript`
invocation the SPA uses, into `src/schema.ts`. The package is `tsc`-built to `dist/`, which is what
a consumer installs.

**Python** runs `openapi-python-client` from the locked environment in
[`tools/pygen`](../tools/pygen), configured by
[`api/codegen-sdk-python.yaml`](../api/codegen-sdk-python.yaml). It generates with `--meta none`:
the package's `pyproject.toml` is hand-written here, because a generated one cannot carry a test
dependency group and should not be rewritten by a generator upgrade.

**Rust** runs [`tools/generate-rust-sdk.sh`](../tools/generate-rust-sdk.sh), which drives the
pinned container. It copies the spec *into* a stopped container and the result back out rather than
bind-mounting: the devcontainer runs docker-outside-of-docker, where a `-v` of this repository's
path resolves against the host's filesystem and silently mounts nothing.

## What is hand-written

Every SDK has a small hand-written seam, and only one, holding what the OpenAPI document cannot say:

| File | What it holds |
|---|---|
| `sdk/go/blacklight.go` | `New`, `WithServiceToken` |
| `sdk/typescript/src/index.ts`, `errors.ts` | `createClient`, `ApiError`, `unwrap` |
| `sdk/python/blacklight/deployment.py` | `connect` |
| `sdk/rust/src/deployment.rs`, `src/lib.rs` | `connect`, the crate's docs |

All four exist for the same two facts. The document declares its one server as the **relative** URL
`/api/v1`, because the SPA is served from the same origin as the API and an absolute URL would pin
every deployment to one host — a client outside the browser has to be told which host, and have the
path appended for it. And a **service token** is presented as `Authorization: Bearer`, which is
mechanical enough that no caller should write it out.

Anything that *can* be expressed in the document belongs in the document. A helper beyond these is a
second description of the API, and the point of generating clients is that there is only one.

The generators do not delete what they did not write, which is what makes this possible — but it
also means each generation step removes its own previous output first (`make sdk-python`,
`tools/generate-rust-sdk.sh`). Without that, the module for an operation *removed* from the document
would stay on disk, keep compiling, and leave the drift gate looking at a clean checkout.

## Adding an endpoint

Nothing extra. Edit `api/openapi.yaml`, run `make generate`, and the operation appears in all four —
see [`docs/api.md`](api.md). What is worth knowing is the one convention the SDKs added:

> A schema may not be named `<OperationId>Response`.

The Go client generates a wrapper type per operation with exactly that name, in the same package as
the schema types, so a schema called `ImportPlanResponse` alongside an operation called `importPlan`
declares one name twice and `sdk/go` stops compiling. `TestNoSchemaCollidesWithAGeneratedResponseWrapper`
in `api/conventions_test.go` refuses it in the document instead, where it costs one rename to fix.
`…Result` is what the rest of the document uses (`LoginResult`, `GuestRegisterResult`).

## Upgrading a generator

Whichever one, the shape is the same: change the pin, run `make generate`, review the diff, run
`make test-sdk`, and commit the regenerated SDK **in the same change**. A pin bumped without the
regenerated output is what the drift gate exists to catch.

- **Go** — `go get -u github.com/oapi-codegen/oapi-codegen/v2 && go mod tidy`, then
  `make tools` to reinstall `./bin/oapi-codegen`.
- **TypeScript** — `npm --prefix sdk/typescript update openapi-typescript`.
- **Python** — edit the version in `tools/pygen/pyproject.toml`, then
  `uv lock --project tools/pygen`. Note that **`ruff` is pinned there too**: it runs as a post-hook
  over the generated code, so a ruff release that changes one line of formatting would otherwise
  appear as codegen drift in a pull request that never touched the API document.
- **Rust** — change both the tag and the digest in `tools/generate-rust-sdk.sh`, then
  `tools/generate-rust-sdk.sh --pull`. Check whether the `models::models::` fix-up at the bottom of
  that script is still needed; the comment there names the upstream issue.

## Known gaps

Three things no generator here models, in every language:

- **The live event stream** (`text/event-stream`) is a long-lived connection, not a document. Read
  it with the HTTP client of your choice; each SDK's README shows how.
- **SAML metadata** (`application/samlmetadata+xml`) is XML, and comes back as bytes.
- **The session cookie and CSRF.** The SDKs authenticate with service tokens only. The cookie's
  client is the SPA, which has its own in [`web/src/api`](../web/src/api). A token can be scoped and
  expired by an administrator; driving the login and MFA endpoints from a script to obtain a cookie
  instead is working around that.

## Publishing

Not wired up. The packages carry version `0.0.0` and no registry credentials exist. Publishing to
pkg.go.dev, npm, PyPI and crates.io from `release.yml` is a separate change: it needs a name
reserved on each registry and four tokens in repository secrets. Until then the SDKs are consumed
from this repository — which for Go is already the normal way (`go get
github.com/bryanster/blacklight/sdk/go`).
