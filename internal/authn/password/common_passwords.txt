# Passwords common enough that an attacker tries them before anything else.
#
# One per line; blank lines and lines beginning with # are ignored. Matching is
# exact and case-insensitive, so entries are written in lower case and there is
# no point listing both "Password1234" and "password1234".
#
# Every entry here is at least MinLength (12) characters. Shorter ones are dead
# weight: the length rule rejects them before the list is consulted. That is
# also why this looks nothing like the usual "top 100" — the passwords everyone
# quotes ("123456", "qwerty", "letmein") are already refused, and what is left
# is the long tail of things people write when told a password must be longer:
# a common short password with digits stuck on, a keyboard walk continued to the
# end of the row, a word doubled, a season and a year.
#
# Selected by hand from the published breach-corpus lists (RockYou, SecLists'
# 10k/100k compilations, the NCSC's released set) plus the patterns that appear
# wherever an administrator sets an initial password. It is deliberately small
# and hand-maintained: M1-002 scopes out breach-corpus lookups, and catching the
# real long tail means a Have I Been Pwned range query or an offline Pwned
# Passwords file rather than a bigger copy of this. That is the follow-up.
#
# Adding an entry is safe at any time — it can only refuse a password, never
# accept one — but it does not invalidate a password already in use. Anyone
# already holding one of these keeps it until they change it or an admin
# resets it.
